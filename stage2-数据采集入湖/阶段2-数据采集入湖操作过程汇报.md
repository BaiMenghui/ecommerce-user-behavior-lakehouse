## 二、ODS层表设计

### 2.1 表基本信息

| 属性 | 说明 |
|------|------|
| **表名** | ods_user_behavior_log |
| **存储引擎** | Hudi (Apache Hudi 0.14.1) |
| **表类型** | MOR (Merge On Read) |
| **分区方式** | 按 dt（日期）分区 |
| **主键字段** | behavior_id |
| **预合并字段** | ts（Unix时间戳） |
| **存储位置** | ~/hudi-bigdata/warehouse/ods_user_behavior_log |
| **总大小** | 57MB |

### 2.2 表结构设计

| 字段名 | 数据类型 | 说明 | 备注 |
|--------|----------|------|------|
| behavior_id | STRING | 行为记录唯一ID | 主键，由 user_id_item_id_ts_behavior_type 拼接生成 |
| user_id | BIGINT | 用户ID | 脱敏用户标识 |
| item_id | BIGINT | 商品ID | 脱敏商品标识 |
| category_id | BIGINT | 商品类目ID | 商品所属类目 |
| behavior_type | STRING | 行为类型 | pv(浏览)/fav(收藏)/cart(加购)/buy(购买) |
| ts | BIGINT | Unix时间戳 | 预合并字段，秒级精度 |
| event_time | TIMESTAMP | 行为发生时间 | 标准日期时间格式 |
| dt | STRING | 日期分区 | YYYY-MM-DD格式，分区字段 |

### 2.3 Hudi表配置参数

| 配置项 | 值 | 说明 |
|--------|---|------|
| hoodie.datasource.write.table.type | MERGE_ON_READ | 表类型：读时合并 |
| hoodie.datasource.write.recordkey.field | behavior_id | 主键字段 |
| hoodie.datasource.write.partitionpath.field | dt | 分区路径字段 |
| hoodie.datasource.write.precombine.field | ts | 预合并字段 |
| hoodie.datasource.write.operation | insert | 写入操作：插入 |
| hoodie.cleaner.policy | KEEP_LATEST_COMMITS | 清理策略：保留最新提交 |
| hoodie.cleaner.commits.retained | 10 | 保留提交数 |
| hoodie.compact.inline | false | 内联压缩：关闭 |

### 2.4 设计说明

**为什么选择 MOR 表？**

- **写入性能更优**：MOR表将增量数据写入log文件，避免每次写入都重写parquet文件，写入延迟更低
- **支持高效增量消费**：MOR表天然支持增量查询，便于后续流式计算场景
- **读时合并**：读取时将base文件（parquet）与delta log合并，适合读少写多的ODS层场景
- **为后续准实时入湖做准备**：如引入Kafka + Structured Streaming，MOR表能更好地处理高频写入

**主键生成策略**

由于原始数据没有唯一的行为ID，采用拼接方式生成：
```
behavior_id = CONCAT(user_id, '_', item_id, '_', ts, '_', behavior_type)
```
- 保证每条行为记录的唯一性
- 可回溯，便于数据核对
- 满足Hudi表主键要求

### 3.1 步骤1：ODS层建表

#### 3.1.1 建表SQL

```sql
CREATE TABLE IF NOT EXISTS ods_user_behavior_log (
    behavior_id STRING COMMENT "行为记录唯一ID",
    user_id BIGINT COMMENT "用户ID",
    item_id BIGINT COMMENT "商品ID",
    category_id BIGINT COMMENT "商品类目ID",
    behavior_type STRING COMMENT "行为类型",
    ts BIGINT COMMENT "Unix时间戳",
    event_time TIMESTAMP COMMENT "行为发生时间",
    dt STRING COMMENT "日期分区"
)
USING hudi
PARTITIONED BY (dt)
OPTIONS (
    type = "mor",
    primaryKey = "behavior_id",
    preCombineField = "ts",
    hoodie.table.name = "ods_user_behavior_log",
    hoodie.datasource.write.recordkey.field = "behavior_id",
    hoodie.datasource.write.partitionpath.field = "dt",
    hoodie.datasource.write.precombine.field = "ts",
    hoodie.datasource.write.operation = "insert",
    hoodie.datasource.write.table.type = "MERGE_ON_READ",
    hoodie.cleaner.policy = "KEEP_LATEST_COMMITS",
    hoodie.cleaner.commits.retained = 10,
    hoodie.compact.inline = "false"
);
```

#### 3.2.2 入湖流程

```
CSV分区数据 (data/cleaned/dt=*/user_behavior.csv)
    │
    ├── 1. 创建临时视图 user_behavior_raw (CSV数据源)
    ├── 2. 生成 behavior_id 主键
    │   (CONCAT(user_id, '_', item_id, '_', ts, '_', behavior_type))
    ├── 3. INSERT INTO ods_user_behavior_log
    └── 4. Hudi MOR表写入完成
```

#### 3.2.3 入湖SQL

```sql
-- 创建临时视图读取CSV数据
CREATE OR REPLACE TEMPORARY VIEW user_behavior_raw (
    user_id BIGINT,
    item_id BIGINT,
    category_id BIGINT,
    behavior_type STRING,
    ts BIGINT,
    event_time TIMESTAMP,
    dt STRING,
    event_hour INT
)
USING csv
OPTIONS (
    path = "/home/BaiMenghui/hudi-bigdata/data/cleaned",
    header = "true",
    mode = "PERMISSIVE"
);

-- 写入Hudi ODS表
INSERT INTO ods_user_behavior_log
SELECT
    CONCAT(CAST(user_id AS STRING), "_", CAST(item_id AS STRING), "_", CAST(ts AS STRING), "_", behavior_type) AS behavior_id,
    user_id,
    item_id,
    category_id,
    behavior_type,
    ts,
    event_time,
    dt
FROM user_behavior_raw
WHERE dt IS NOT NULL AND dt != "";
```

### 4.2 MOR表文件说明

MOR（Merge On Read）表包含两类文件：

| 文件类型 | 说明 |
|----------|------|
| **Base File** (.parquet) | 基础数据文件，列存格式，存储已提交的全量数据 |
| **Delta Log File** (.log) | 增量日志文件，行存格式，存储最近的写入变更 |

**读取时：** Hudi将Base File与Delta Log合并后返回结果，实现"读时合并"。
