## 二、大屏原型设计稿（4+2+1 布局）

```
┌──────────────────────────────────────────────────────────────┐
│ 头部通栏（1行）：平台标题 · 实时时钟(秒级) · 健康状态灯 · 日期切换 │
├──────────┬────────────────────────┬──────────────────────────┤
│ KPI 卡   │  DAU·GMV 双轴趋势图     │  商品销量 Top10 横向条形   │
│ 6 张竖排  ├────────────────────────┼──────────────────────────┤
│ DAU      │  转化漏斗 pv→fav→cart→buy│  类目销售占比 环状饼图     │
│ 新增用户  │  （三段转化率标注）       │  （Top15+其他 聚合）      │
│ 老客/订单 │                        │                          │
│ GMV/客单价│                        │                          │
├──────────┴────────────┬───────────┴──────────────────────────┤
│ 24小时行为流量 堆叠柱   │  用户行为分布 环形图（pv/fav/cart/buy）│
└───────────────────────┴──────────────────────────────────────┘
```

设计要点：

1. **头部**：平台名称 + 每秒刷新时钟（体现"实时"观感）+ `/api/health` 驱动的状态灯（UP 绿/异常红，30 秒轮询）+ 24 天日期下拉切换（默认末位 `2017-12-03`）。
2. **中部三列**：左列 6 张 KPI 卡（DAU、新增、老客、订单、GMV、客单价，新老占比作副标注）；中列上趋势下漏斗；右列上 Top10 下列占比。
3. **底部**：24 小时堆叠柱（按行为类型分色）+ 行为分布环形图（由小时数据按类型求和派生，不另调接口）。
4. **视觉**：深色科技风——底色 `#0B1020`、卡片 `#111827`、边框 `#1E293B`、主色青 `#00D4FF` / 紫 `#7C3AED`。
5. **全局联动**：切换日期后，KPI/漏斗/Top10/占比/小时图五个区块统一按新 `dt` 重新拉取；DAU 趋势为 24 天全量不受 `dt` 影响。

### 3.3 关键设计决策

1. **字段兼容层**：`format.js` 与各组件内置键名映射（`pv_cnt/pv`、`hour/hour_of_day`、`buy_share_ratio/share/ratio`），后端字段名微调无需改前端主逻辑。
2. **比率口径兼容**：`formatRatio` 同时兼容 `0.0321`（小数）与 `32.1`（百分数）两种后端返回形态，避免阶段4口径调整引发前端显示错误。
3. **类目聚合**：`/api/category-share` 每日类目数不等（2017-11-25 为 3,281 项、2017-12-03 为 3,556 项），前端强制聚合为 Top15 + 「其他」再渲染，严禁全量画饼图。
4. **图表统一封装**：8 个图表组件共用 `useEChart` composable，统一 init/setOption/resize/dispose 生命周期。

## 七、浏览器实测验收与两个前端 Bug 修复记录

> 经验教训（再次验证）：Vite dev 按需编译，**构建通过 ≠ 运行无错**，必须浏览器实测。

### Bug 1：`format.js` 缺少 `pickNum/pickStr` 导出（阻断级）

- **现象**：浏览器打开后页面整体挂载失败，控制台 SyntaxError——5 个组件从 `format.js` 导入 `pickNum/pickStr`，但这两个函数误写在了 `chart.js` 中。
- **修复**：在 `src/utils/format.js` 末尾补齐两个函数，语义与 `chart.js` 中实现完全一致（`pickNum` 跳过无法转数字的键默认 0；`pickStr` 默认空串）。
- **验证**：修复后页面正常挂载，8 区块 DOM 全部渲染。

### Bug 2：ECharts 容器 0×0 报 "Can't get DOM width or height"

- **现象**：验收浏览器为 headless 环境，`window.innerWidth/innerHeight = 0`，布局容器无尺寸，ECharts init 失败并输出警告。
- **修复**：`src/composables/useEChart.js` 增加 **ResizeObserver 兜底**——onMounted 创建图表后观察容器，尺寸变为有效（`clientWidth>0 && clientHeight>0`）时自动 `chart.resize()`；onBeforeUnmount 时 `ro.disconnect()` 防泄漏。
- **复验**（强制视口实验）：向 headless 浏览器注入 `documentElement/body = 1600×900` 尺寸后，ResizeObserver 触发，**6/6 图表 canvas 全部获得有效尺寸**（容器实测 640×231、640×244、580×231、580×244、940×196、580×196），`toDataURL()` 长度 46,070~254,878 字节（非空白），证明 6 个图表实际渲染成功；控制台无新增 JS 错误。正常桌面浏览器窗口下不会出现 0×0 初始态。
