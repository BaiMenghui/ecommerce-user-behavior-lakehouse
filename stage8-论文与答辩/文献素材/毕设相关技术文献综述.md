### 文献1：Lakehouse: A New Generation of Open Platforms Unified Data Warehousing and Data Lake

| 属性 | 说明 |
|------|------|
| **作者** | Armbrust, M., Ghodsi, A., Xin, R., Zaharia, M. |
| **发表会议/期刊** | CIDR 2021 (Conference on Innovative Data Systems Research) |
| **发表年份** | 2021 |
| **来源链接** | [InfoQ](https://www.infoq.cn/article/n8d436zu9qv1uyseiqcw) |

**核心内容：**

Databricks在CIDR 2021上首次正式提出Lakehouse概念。论文指出传统数据仓库和数据湖各有优缺点：数据仓库提供ACID事务、数据版本管理和 Schema管理，但成本高昂且难以处理非结构化数据；数据湖成本低、支持多种数据格式，但缺乏事务保证和查询性能优化。Lakehouse架构通过在数据湖之上增加元数据层和事务层，实现了两者的优势融合。

**与毕设的关联：**

本文是湖仓一体架构的奠基性论文，为毕设的架构设计提供了理论依据。毕设采用Hudi作为湖仓一体的核心组件，正是基于Lakehouse架构理念。

**引用要点：**
> "Lakehouse architectures combine the best features of data lakes (low-cost storage, open formats, support for any data type) with the best features of data warehouses (ACID transactions, data versioning, schema management, and query performance)."

### 文献5：Modern Table Formats for Data Lakehouse Architectures: A Comprehensive Analysis of Apache Iceberg, Delta Lake, and Apache Hudi

| 属性 | 说明 |
|------|------|
| **作者** | (多作者) |
| **发表平台** | Semantic Scholar |
| **发表年份** | 2025 |
| **来源链接** | [Semantic Scholar PDF](https://pdfs.semanticscholar.org/71b2/c6aa3fd6a972fbe36febec4975b77de247d8.pdf) |

**核心内容：**

对三大主流开放表格式（Apache Iceberg、Delta Lake、Apache Hudi）进行了全面对比分析。论文指出Hudi源自Uber工程团队，专注于流式数据摄入模式和高效的变更数据捕获（CDC）处理。论文详细分析了各格式的技术特点：

- **Hudi的COW模式**：在更新时生成修改文件的新版本，确保读查询无合并开销，但写入放大显著
- **Hudi的MOR模式**：将更新推迟到单独的delta log，降低写入延迟和存储开销，但引入查询时的合并复杂度
- **架构灵活性**：使得组织可以根据特定延迟和吞吐量需求进行优化

**与毕设的关联：**

毕设选择Hudi MOR表作为ODS层存储格式，本文为该选型决策提供了直接的理论依据。

### 文献9：What is ACID on a Data Lake?

| 属性 | 说明 |
|------|------|
| **作者** | Apache Hudi Community |
| **发表平台** | Apache Hudi官方博客 |
| **发表年份** | 2026 |
| **来源链接** | [Hudi Blog](https://hudi.apache.org/blog/2026/07/17/what-is-acid-on-a-data-lake/) |

**核心内容：**

详细阐述Hudi如何在数据湖上实现ACID事务保证：

- **原子性（Atomicity）**：500文件的Spark作业在文件320处失败时，已写入的文件不会影响数据一致性
- **一致性（Consistency）**：Hudi的时间线（Timeline）机制保证表状态的一致性
- **隔离性（Isolation）**：时间线服务实现并发写入的隔离
- **持久性（Durability）**：每次提交持久化到对象存储

Hudi使用TrueTime风格的单调递增时间戳为每个操作打上时间戳，使得即使在独立进程之间，操作也是全局有序的。

### 文献22：A Dimensional Modeling Manifesto

| 属性 | 说明 |
|------|------|
| **作者** | Kimball, R. |
| **发表平台** | Kimball Group |
| **发表年份** | 1997 |
| **来源链接** | [Kimball Group](https://www.kimballgroup.com/1997/08/a-dimensional-modeling-manifesto/) |

**核心内容：**

Kimball发表的维度建模宣言，定义了维度建模的核心原则：

- 每个维度模型由一个包含多部分键的**事实表**和一组较小的**维度表**组成
- 每个维度表有一个单部分主键，与事实表多部分键的一个组件精确对应
- 这种特征性的"星型"结构通常称为**星型连接（Star Join）**

**与毕设的关联：**

为毕设的DWD层设计（用户行为事实表 + 用户/商品/日期维度表）提供了理论框架。

| 属性 | 说明 |
|------|------|
| **作者** | Kimball Group |

Kimball维度建模技术参考，描述了星型模式和OLAP立方体的关系：

- 可等同于关系型星型模式或从中派生
