# 工具库与算法使用清单

> 《电商用户行为湖仓分析平台》全部工具库（15）与算法（26）的使用方法与使用位置。
> 用途：论文"相关技术"章节素材、答辩讲代码对照表。

---

## 第一部分 工具库（15 个）

### 1. pandas
- **使用方法**：`read_csv` 加载数据；`dropna/drop_duplicates/isin` 做缺失、去重、白名单过滤；`to_datetime(unit='s')` + `.dt` 访问器做时间派生；`groupby` 分组落盘；`value_counts/nunique` 做统计。
- **使用位置**：stage1-数据源准备/scripts/stage1_data_clean.py（八步清洗，L72-213）、stage1_data_explore.py（数据探查）。

### 2. NumPy
- **使用方法**：pandas 的底层依赖，提供 ndarray 数值容器与向量化运算；数值边界比较（时间戳上下限）依赖其类型系统。
- **使用位置**：随 pandas 隐式使用，stage1 清洗与探查全程。

### 3. PySpark —— Spark SQL / DataFrame
- **使用方法**：`spark.sql()` 执行分层 ETL SQL；DataFrame API 的 `select/where/join` 做加工；`CACHE` 缓存中间表。
- **使用位置**：stage2 入湖（run_ods_ingestion.sh 调 spark-sql）、stage3 三个 ETL（stage3_dim/dwd/dws_etl.py）、stage4 指标（stage4_ads_etl.py）。

### 4. PySpark —— Window 窗口函数
- **使用方法**：`Window.partitionBy(键).orderBy(时间)` 定义窗口；`F.lag()` 取邻行；`F.sum().over(rowsBetween(unboundedPreceding, currentRow))` 做累计求和。
- **使用位置**：stage3-湖仓分层建模/stage3_dwd_etl.py L193-230（30 分钟会话切分核心）。

### 5. PySpark —— Structured Streaming
- **使用方法**：`spark.readStream` 读 Kafka；`from_json` 按 schema 解析；`foreachBatch` 微批处理函数内写 Hudi；`checkpointLocation` 保存进度。
- **使用位置**：stage2-数据采集入湖/Kafka流式入湖/streaming_to_hudi.py（批流一体实验）。

### 6. Apache Hudi
- **使用方法**：建表时配置 `hoodie.datasource.write.table.type`（MERGE_ON_READ/COPY_ON_WRITE）、主键、`precombineField`、分区字段；写入自动 Upsert；`readOptions` 指定 `BEGIN_INSTANTTIME` 做增量查询。
- **使用位置**：stage2 建表 SQL（ODS=MOR）、stage3_dim_ddl.sql（DIM=COW）、stage3_dws_ddl.sql（DWS=COW）、stage4_ads_ddl.sql（ADS=COW）、hudi_realtime_verify.py（commit 级增量验证）。

### 7. Apache Kafka
- **使用方法**：`kafka_producer.py` 按 500 条/秒向 topic `user_behavior_stream` 生产消息；consumer 端由 Structured Streaming 订阅。
- **使用位置**：stage2-数据采集入湖/Kafka流式入湖/kafka_producer.py、start_kafka.sh。

### 8. Spark MLlib
- **使用方法**：`Pipeline + VectorAssembler` 组装特征向量，`KMeans.setK(k).fit()` 聚类（规划中的用户分层扩展）。
- **使用位置**：stage7 创新实验规划项（K-means 用户分层，当前以规则分层落地）。

### 9. Hadoop HDFS
- **使用方法**：作为 Hudi 表的底层文件系统，warehouse 目录按表/分区组织；`hdfs dfs` 命令管理。
- **使用位置**：全链路存储底座（docker-compose 编排于 stage0）。

### 10. Hive Metastore
- **使用方法**：Spark 以 `spark.sql.catalogImplementation=hive` 接入，统一管理库表元数据与分区信息；`SHOW PARTITIONS` 做分区校验。
- **使用位置**：全部建表与查询（stage2-4）；hms-元数据修复/（同步异常排查脚本）。

### 11. Spring Boot
- **使用方法**：`@RestController + @GetMapping` 声明 8 个接口；`Service` 层启动时加载 CSV 建内存索引；统一响应体 `{code,msg,data}`。
- **使用位置**：stage5-数据服务层/springboot-service/src/.../controller/AdsController.java、service/AdsCsvService.java。

### 12. Redis
- **使用方法**：作为首选缓存，`SET key value EX ttl` 存指标 JSON；不可用时服务自动降级。
- **使用位置**：stage5 服务层缓存层（config/CacheConfig.java）。

### 13. Caffeine
- **使用方法**：JVM 内嵌缓存，`Caffeine.newBuilder().expireAfterWrite(ttl).maximumSize()` 构建；Redis 失效时兜底。
- **使用位置**：stage5 config/CacheConfig.java（实测运行即 caffeine 模式，大屏头部徽标可见）。

### 14. Vue3 + ECharts + Vite
- **使用方法**：Vite 启动开发服务（代理转发 API）；Vue3 组合式 API 组织 7 个图表组件；ECharts 按面板渲染折线/漏斗/柱状/环形/热力；切日期用 `Promise.all` 并发拉 6 接口联动。
- **使用位置**：stage6-可视化大屏/vue-dashboard/src/（App.vue、components/ 八个组件）。

### 15. Docker Compose
- **使用方法**：一份 yml 声明 HDFS/Hive/Spark 等服务、网络与挂载卷，`docker-compose up -d` 一键拉起。
- **使用位置**：stage0-环境搭建/docker-compose.yml。

## 第二部分 算法（26 个）

### 数据清洗与去重

**1. 哈希去重（Hash-based Deduplication）**
- 原理：对记录键值计算哈希，哈希集合判重，O(n)。
- 方法/位置：`drop_duplicates(subset=[user_id,item_id,timestamp,behavior_type])`，stage1_data_clean.py L140——四字段业务主键去重。

**2. Timsort 排序**
- 原理：归并+插入混合排序，O(n log n)，对近乎有序数据近乎 O(n)。
- 位置：pandas `sort_values`、Spark `orderBy("ts")`（会话切分前排序）底层。

**3. 内容指纹（拼接主键）**
- 原理：由业务字段拼接生成天然唯一标识，避免自增 ID 重跑冲突。
- 位置：stage2_ods_ingestion.sql——`behavior_id = user_id_item_id_ts_行为类型`。

**4. 规则过滤（白名单/边界校验）**
- 原理：枚举合法值域与合理时间区间，域外即剔除。
- 位置：`isin(['pv','fav','cart','buy'])`（clean L162）、时间戳上下限 TS_MIN/TS_MAX（L58-59）。

**5. 分区派生（时间字段展开）**
- 原理：`to_datetime(unit='s')` 解析 Unix 秒，`.dt.strftime('%Y-%m-%d')` 与 `.dt.hour` 派生 dt/hour。
- 位置：stage1_data_clean.py L182-191。

### 分布式计算

**6. MapReduce 分组聚合（Shuffle Aggregation）**
- 原理：按 key 重分区（shuffle）后组内聚合。
- 位置：全部 `groupBy().count/sum/agg`（stage3 各 ETL、stage4 指标 SQL 的 GROUP BY）。

**7. HyperLogLog 基数估计**
- 原理：哈希后按前缀分桶，以桶内最大前导零估算去重基数，误差约 2%。
- 位置：`countDistinct("user_id"/"session_id")` 大数据量时 Spark 的近似执行路径（stage3_dws_etl.py L166）。

**8. Top-K 选择**
- 原理：按指标排序取前 K（可用堆优化至 O(n log k)）。
- 位置：stage4_ads_etl.py——热销商品 Top10，购买次数降序、并列按 item_id 升序。

**9. 微批处理（Micro-Batching）**
- 原理：把无界流切成小批次，每批走批处理引擎，兼得吞吐与延迟。
- 位置：streaming_to_hudi.py 的 `foreachBatch`。

**10. 检查点算法（Checkpointing）**
- 原理：周期性持久化消费进度，故障后从断点恢复，保证恰好一次语义。
- 位置：streaming_to_hudi.py 的 `checkpointLocation` 配置。

**11. 分区裁剪（Partition Pruning）**
- 原理：查询条件含分区键时只扫描命中分区目录。
- 位置：所有 `WHERE dt='...'` 指标查询；大屏切日期即秒级的原因之一。

**12. 谓词下推（Predicate Pushdown）**
- 原理：过滤条件推到数据读取层，先过滤后传输。
- 位置：Spark Catalyst 优化器对 Parquet/Hudi 读取自动执行。

### 窗口与序列

**13. SQL 窗口函数（Window Function）**
- 原理：分组排序后不折叠行、逐行计算。
- 位置：stage3_dwd_etl.py 全部会话逻辑。

**14. Lag 移位访问（Offset Access）**
- 原理：窗口内取前/后第 n 行值。
- 位置：`F.lag("ts").over(w)`（L200）取同用户上一条行为时间。

**15. 前缀和（Prefix Sum）**
- 原理：0/1 标记序列逐位累加，任意位置的和即编号。
- 位置：`F.sum("is_new_session").over(累计窗口)` 生成 session_seq（L228-230）——30 分钟会话切分的第三步。

### 存储引擎

**16. MVCC 多版本并发控制**
- 原理：提交生成新版本快照，读写互不阻塞。
- 位置：Hudi Timeline，快照查询/增量查询/时间旅行的基础。

**17. LSM-Tree 思想（日志结构合并）**
- 原理：写只追加日志文件，读时合并，写快读慢。
- 位置：MOR 表——ODS/DWD 写多读少场景。

**18. Copy-on-Write（写时复制）**
- 原理：写时重写底层文件，读零合并。
- 位置：COW 表——DIM/DWS/ADS 读多写少场景。

**19. 布隆过滤器（Bloom Filter）**
- 原理：位数组+多哈希 O(1) 判"一定不存在/可能存在"。
- 位置：Hudi 默认主键索引，入湖 Upsert 快速判存。

**20. 列式存储（Columnar Storage）**
- 原理：按列组织数据，同列高压缩、查询可跳列。
- 位置：Parquet 底层文件格式（Hudi/COW 基文件）。

**21. Kryo 序列化**
- 原理：二进制序列化替代 Java 原生，体积小速度快。
- 位置：`spark.serializer=KryoSerializer`（stage2 入湖配置）。

### 统计分析

**22. 稀疏矩阵度量**
- 原理：实际交互数 / (用户数×商品数)。
- 位置：stage1_data_explore.py L205-212——交互矩阵稀疏度与密度。

**23. 漏斗转化分析**
- 原理：逐级留存率刻画流程流失。
- 位置：stage4_ads_etl.py——浏览→收藏→加购→购买三段转化率。

**24. 恒等式对账（多口径交叉校验）**
- 原理：同一事实多种聚合口径数学上必相等，不等即有错。
- 位置：stage3_dws_check.py（三角核对：明细=Σ用户=Σ商品=Σ类目）、stage4_ads_check.py（21 项交叉校验）。

**25. 规则分层（Rudder-based Segmentation）**
- 原理：以首末活跃日期等规则阈值划分用户生命周期。
- 位置：stage3_dim_etl.py L147——`when(first==last,"new")` 链式分层（K-means 的可解释替代）。

**26. K-means 聚类（K-Means Clustering）**
- 原理：随机选 K 个中心，迭代"就近分配→中心移均值"至收敛。
- 位置：规划扩展项（spark MLlib），对 dws_user_action_day 的 R/F/M 特征做用户价值分层；当前以规则分层落地。

### 缓存策略

**27. Cache-Aside 旁路缓存**
- 原理：先查缓存→未命中回源→回填。
- 位置：AdsService 读取指标链路。

**28. W-TinyLFU 淘汰算法**
- 原理：Count-Min Sketch 频率统计 + 窗口桶，保留高命中项。
- 位置：Caffeine 底层（stage5 CacheConfig.java）。

**29. TTL 过期策略**
- 原理：每条缓存带存活时间，到期失效保证时效。
- 位置：指标缓存的 expireAfterWrite 配置。

## 组合叙述（答辩用）

> 清洗层用 **pandas 的哈希去重与分组聚合**做八步清洗；建模层用 **窗口函数 + 前缀和**实现 30 分钟会话切分；存储层按读写特征混选 **LSM 思想的 MOR 表**与**写时复制的 COW 表**，主键判重靠**布隆过滤器**；指标层用 **MapReduce 分组聚合**与 **Top-K 选择**产出漏斗/排行；质量层以**恒等式对账**（三角核对+21 项交叉校验）保证可信；服务层以 **Cache-Aside + W-TinyLFU 缓存**支撑大屏秒级响应。
