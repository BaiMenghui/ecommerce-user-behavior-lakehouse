## 一、选题主要内容（指主要做什么、包含哪些主要功能？）

> 对应 PPT：P03 数据现状 · P09 研究目标 · P10 五环节 · P11–P13 架构与核心环节 · P14–P17 分层设计
> 建议字数 600–800 字。写法：先一句总述，再分模块列功能。

**【可直接抄入的正文】**

本课题以阿里天池 UserBehavior 公开数据集为数据源（全量约 1 亿条行为记录，本课题抽取 100 万条进行验证，时间区间为 2017 年 11 月 25 日至 12 月 3 日，共 9 天；字段含用户 ID、商品 ID、类目 ID、行为类型、时间戳，行为覆盖浏览 pv、收藏 fav、加购 cart、购买 buy 四类），基于湖仓一体架构设计并实现一套电商用户行为分析平台，完成从原始日志到业务指标的端到端处理。系统包含以下五个功能模块：

**（1）数据采集模块。** 对原始 CSV 进行全量数据探查（用户/商品规模统计、行为分布占比、缺失值与重复值检查），执行标准化清洗：缺失值填充、重复值剔除、时间戳转换为标准日期时间格式、按自然日完成分区。清洗后经 Spark 批量写入 Apache Hudi 的 ODS 贴源层，并完成行数、非空、日期三重校验；同时预留 Kafka + Spark Structured Streaming 的准实时入湖通道。

**（2）数据存储模块。** 以 HDFS 为底层分布式存储、Hive Metastore 统一管理元数据，构建 Apache Hudi 表体系。按各层读写特性差异化选型：ODS、DWD 写多读少采用 MOR（Merge On Read）表，DIM、DWS、ADS 读多写少采用 COW（Copy On Write）表，以取得写入吞吐与查询性能之间的平衡。该层对外提供 ACID 事务、增量查询与时间旅行能力。

**（3）数据建模模块。** 遵循 Kimball 维度建模理论，构建 ODS → DIM → DWD → DWS → ADS 五层数仓：3 张维度表（dim_user、dim_item、dim_date）、1 张用户行为事实表（dwd_user_behavior_fact）、3 张主题宽表（用户、商品、类目）、5 张 ADS 指标表。在 DWD 层执行去重、异常过滤、维度退化，并实现基于 30 分钟超时规则的会话切分，支撑用户行为路径与跳失分析。

**（4）指标计算模块。** 基于 Spark SQL 从 DWS 主题宽表计算四类业务指标：整体运营 KPI（DAU、订单总量、GMV、客单价）、转化漏斗（浏览→加购→购买三步转化）、商品销售洞察（热销 Top10 商品、类目销售占比）、业务趋势研判（日 GMV 走势、小时流量峰谷），并输出标准化指标口径文档，明确各指标的计算公式、统计粒度与业务含义。

**（5）数据服务与可视化模块。** 使用 SpringBoot 构建 RESTful API 封装 ADS 层指标，引入 Redis 缓存高频查询结果，同时支持 CSV/JSON 静态导出；前端基于 Vue3 + ECharts 实现可视化大屏，包含 DAU 趋势折线、GMV 数字卡、转化漏斗、商品/类目排行榜、活跃时段热力图、行为构成饼图六类视图。

此外，通过 Docker Compose 编排九项服务实现环境一键复现，梳理并绘制完整的数据血缘关系图谱，并设计存储模式性能对比实验，对比传统 Hive 分区表与 Hudi COW/MOR 表在典型电商查询场景下的耗时与吞吐量差异。

## 二、选题意义与应用价值（查找文献、资料后确定）

> 对应 PPT：P04 架构之痛 · P05 三重意义 · P06 技术演进 · P07 架构对比 · P08 研究缺口
> 建议字数 500–700 字。**模板明确要求"查找文献后确定"，所以开头必须有一段文献综述**，这是评审重点。

**【可直接抄入的正文】**

**（一）国内外研究现状**

数据架构近三十年经历了三次演进：20 世纪 90 年代以 Teradata、Oracle 为代表的数据仓库，事务与查询能力强但成本高昂且只能容纳结构化数据；2010 年前后以 Hadoop、S3 为代表的数据湖，存储成本低、格式开放，但缺乏事务保证与质量管控，易退化为"数据沼泽"；2020 年以来，Armbrust 等人在 CIDR 2021 提出 Lakehouse（湖仓一体）架构，主张在开放直接访问格式（如 Apache Parquet、ORC）之上增加事务元数据层，从而在一个平台上同时支持 BI 与机器学习负载。开放表格式 Apache Hudi、Apache Iceberg、Delta Lake 是该架构的核心实现。

国内方面，陈氢等从数据治理视角对湖仓一体架构进行了研究，指出其在数据共享与一致性保障上的优势。在电商用户行为分析领域，已有成果多聚焦上层算法与用户建模，例如朱志国等基于微观行为洞察构建了电商用户多周期购买兴趣的融合表征模型，陈海燕等将改进 RFM 模型与 K-means 聚类结合用于淘宝用户分群。

综观现有研究，仍存在三点不足：一是企业级生产案例较多、面向中小数据规模且可完整复现的开源教学案例稀缺；二是百万级数据量下湖仓实践缺少系统的可行性验证与性能记录；三是采集—建模—服务—可视化全链路的工程文档较为少见。本课题正是针对上述缺口展开。

**（二）理论意义**

验证开放表格式 Apache Hudi 在中小规模电商分析场景下的可行性；补充 Kimball 维度建模方法在湖仓环境中的落地实践案例；通过严格的分层规范与血缘梳理，佐证湖仓一体架构在数据治理方面的有效性。

**（三）应用价值**

打通采集、存储、处理、服务、展示全链路，形成可复用的技术选型与分层建模方案，为同类中小企业构建低成本数据平台提供参考；输出 DAU、GMV、转化漏斗、商品排行等指标，帮助运营定位转化流失点与增长机会；全部环境由 Docker Compose 一键编排，脚本与文档齐备，具备良好的可复现性与工程参考价值。

## 三、实现方案（主要指技术路线，用到的相关技术）

> 对应 PPT：P14 六层架构 · P15 技术栈矩阵 · P16 Kimball 建模 · P17 五层数仓 · P18 性能实验 · P19 服务与可视化
> 建议字数 700–900 字。这是最实质的一节，评审主要看这里。

**【可直接抄入的正文】**

**（一）总体技术路线**

采用"数据源 → 采集 → 存储 → 处理 → 服务 → 展示"六层单向依赖架构，数据沿链路单向流动，上层只依赖下一层，不跨层引用，每层可独立重跑，指标口径在 ADS 层统一固化，避免"两套系统、两份数据"。

**（二）开发环境与技术选型**

| 层次 | 技术 | 版本 |
|---|---|---|
| 存储引擎（湖仓核心） | Apache Hudi | 0.14.x |
| 分布式存储 | Hadoop HDFS | 3.3.x |
| 元数据管理 | Hive Metastore | 3.x |
| 计算引擎 | Apache Spark | 3.4.x |
| 消息队列（准实时预留） | Kafka | 3.x |
| 后端服务 | SpringBoot | 2.x |
| 缓存 | Redis | 7.x |
| 前端可视化 | Vue3 + ECharts | 5.x |
| 容器化部署 | Docker Compose | 24.x |

全部组件通过 docker-compose.yml 统一编排，实现一键启动与跨机复现。

**（三）分层设计与实现要点**

1. **ODS 操作数据层**：建 Hudi MOR 表 ods_user_behavior_log，按 dt 分区，主键 behavior_id，原始字段不做加工，保证可回溯。
2. **DIM 维度层**：COW 表，构建用户、商品、时间三张维度表，提供三类分析视角。
3. **DWD 明细层**：MOR 表 dwd_user_behavior_fact，执行去重与异常过滤、维度退化，并使用 Spark 窗口函数（lag 取相邻事件时间）实现 30 分钟超时会话切分。
4. **DWS 汇总层**：COW 表，按"实体 × 天"粒度构建用户日活、商品热度、类目汇总三张主题宽表，减少上层计算量。
5. **ADS 应用数据层**：COW 表，存储 DAU、GMV、转化率、排行榜等最终指标结果，优化表结构以适配大屏查询。

**（四）建模方法**

采用 Kimball 四步建模法：① 选业务过程（用户的一次浏览/收藏/加购/购买行为）；② 声明粒度（一行 = 一个用户对一个商品的一次行为）；③ 确定维度（dim_user、dim_item、dim_date 及退化会话维度）；④ 确定事实（行为次数、行为类型、时间间隔、会话序号），最终形成以事实表为中心、三类维度环绕的星型模型。

**（五）数据服务与可视化**

SpringBoot 提供统一响应格式的 RESTful 接口，Redis 缓存热点指标并设置 TTL 自动过期，未命中时回源 ADS 并回填；前端 Vue3 + ECharts 按"左侧 KPI 卡、中间趋势/漏斗、右侧排行占比、底部小时级监控"布局，实现响应式自适应。

**（六）性能对比实验方案**

选取用户行为统计、商品销售分析、分区增量查询三类典型场景，在传统 Hive 分区表、Hudi COW 表、Hudi MOR 表上执行相同 SQL，记录查询耗时与吞吐量；固定 Spark 资源配置，每轮重复 3 次取平均值并剔除冷启动首轮，唯一变量为表类型。预期查询耗时相对 Hive 基线降低 30% 以上。
