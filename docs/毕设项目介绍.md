# 电商用户行为湖仓分析平台

> 基于湖仓一体架构的电商用户行为全链路分析系统

---

## 项目概述

电商用户行为湖仓分析平台是一个以 **Apache Hudi** 为核心存储引擎、**Apache Spark** 为计算引擎、基于 **湖仓一体（Lakehouse）架构** 的全链路数据分析系统。项目围绕电商用户行为数据，构建了从数据采集、存储、处理、服务到可视化的完整技术栈，实现了百万级行为记录的实时入湖、分层建模与交互式分析。

项目采用 **五层数仓架构（ODS → DIM → DWD → DWS → ADS）** 与 **Kimball 维度建模** 理论，严格遵循大数据行业分层规范，覆盖数据工程全生命周期。前端通过 Vue3 + ECharts 实现可视化大屏，后端通过 SpringBoot 提供 RESTful API 服务，最终产出日活用户数、成交总额、转化漏斗、商品排行等核心业务指标。

## 研究背景与意义

### 背景

随着电商行业的快速发展，用户在平台上的浏览、收藏、加购、购买等行为数据以指数级增长。这些行为数据蕴含着巨大的商业价值——通过分析用户行为模式，可以优化商品推荐、提升转化率、辅助运营决策。然而，传统的数据处理架构面临诸多挑战：

- **数据仓库** 提供了ACID事务和高性能查询，但成本高昂，难以处理海量半结构化数据
- **数据湖** 存储成本低、格式开放，但缺乏事务保证，数据质量难以管控
- **传统ETL链路** 时效性差，无法满足实时分析需求

湖仓一体（Lakehouse）架构的出现融合了两者的优势。Apache Hudi 作为开放表格式的代表，在数据湖之上提供了ACID事务、增量查询、时间旅行等能力，为构建低成本、高可靠的分析平台提供了新的技术路径。

### 意义

| 维度 | 说明 |
|------|------|
| **理论意义** | 验证湖仓一体架构在中小规模电商场景下的可行性，丰富Kimball维度建模在湖仓环境下的实践案例 |
| **实践价值** | 构建完整的全链路数据平台，覆盖从原始数据到业务指标的端到端流程，为同类项目提供可参考的技术方案 |
| **业务价值** | 通过用户行为分析发现业务洞察，如用户活跃度趋势、商品热度排名、转化漏斗瓶颈等，辅助电商运营决策 |

## 数据仓库分层设计

### 五层架构总览

项目采用行业主流的 **五层数仓架构**，每一层职责明确，数据自下而上逐层加工。

| 层级 | 全称 | 中文名称 | 核心职责 | Hudi表类型 |
|------|------|----------|----------|-----------|
| **ODS** | Operational Data Store | 操作数据层 | 原始数据接入，保持数据原貌 | MOR |
| **DIM** | Dimension | 维度层 | 维度表构建，提供分析视角 | COW |
| **DWD** | Data Warehouse Detail | 明细数据层 | 数据清洗、维度关联、明细事实 | MOR |
| **DWS** | Data Warehouse Summary | 汇总数据层 | 主题宽表构建，预聚合计算 | COW |
| **ADS** | Application Data Store | 应用数据层 | 业务指标计算，直接服务应用 | COW |

### 数据流转方向

```
ODS（原始数据）
  │
  ├──→ DIM（维度表：用户 / 商品 / 时间）
  │        │
  ▼        ▼
DWD（明细事实表：关联维度，清洗脱敏）
  │
  ▼
DWS（主题宽表：用户日活 / 商品热度 / 类目汇总）
  │
  ▼
ADS（应用指标：DAU / GMV / 转化率 / 排行榜）
```

## 五个核心环节

### 环节一：数据采集

将阿里天池 UserBehavior 数据集经过清洗后批量写入 Hudi ODS 层，同时预留 Kafka 准实时采集接口。

| 属性 | 说明 |
|------|------|
| **数据源** | 阿里天池 UserBehavior.csv（100万+条行为记录） |
| **采集方式** | Spark 批量读取 CSV → 写入 Hudi ODS 表 |
| **数据格式** | user_id, item_id, category_id, behavior_type, timestamp |
| **行为类型** | pv（浏览）/ fav（收藏）/ cart（加购）/ buy（购买） |
| **目标表** | ods_user_behavior_log（Hudi MOR 表，按 dt 分区） |
| **数据校验** | 行数核对、字段非空检查、日期范围校验 |

### 环节二：数据存储

基于 Hudi 构建湖仓一体存储底座，支持 MOR 和 COW 两种表类型，满足不同场景的读写需求。

| 表类型 | 适用场景 | 项目中的应用 |
|--------|----------|-------------|
| **MOR** (Merge On Read) | 写入频繁、增量更新多 | ODS 贴源层、DWD 明细层 |
| **COW** (Copy On Write) | 读多写少、查询性能要求高 | DIM 维度层、DWS 汇总层、ADS 应用层 |

**核心特性：**
- ACID 事务：确保数据写入的原子性和一致性
- 增量查询：支持按提交时间增量读取，降低下游计算量
- 时间旅行：可查询历史任一时刻的数据快照
- 自动清理：保留最近 N 个提交，控制存储膨胀

### 环节三：数据处理

以 Kimball 维度建模理论为指导，完成从 ODS 到 DWD、DWS、ADS 的全链路 ETL 加工。

**DIM 维度层：**
- `dim_user` — 用户维度（用户等级、活跃日期、行为累计）
- `dim_item` — 商品维度（商品状态、曝光日期、交互累计）
- `dim_date` — 时间维度（年月日、季度、周、周末标识）

**DWD 明细层：**
- `dwd_user_behavior_fact` — 用户行为事实表
- 数据清洗（去重、异常过滤）
- 维度关联（行为编码、日期代理键、退化维度）
- 会话划分（30分钟超时规则的 Session 切分）

**DWS 汇总层：**
- 用户日活主题宽表
- 商品热度主题宽表
- 类目汇总主题宽表

**ADS 应用层：**
- DAU（日活用户数）
- GMV（成交总额）
- 转化率（浏览→加购→购买漏斗）
- 商品/类目排行榜

### 环节四：数据服务

基于 SpringBoot 构建 RESTful API 服务层，配合 Redis 实现热点数据缓存，为前端可视化提供数据支撑。

| 模块 | 说明 |
|------|------|
| **接口设计** | 统一响应格式、分页查询、按日期范围过滤 |
| **指标接口** | DAU趋势、GMV统计、转化率、排行榜等 |
| **缓存策略** | Redis 缓存热点指标，TTL 自动过期 |
| **数据导出** | 支持 CSV 格式批量导出 |

### 环节五：数据展示

基于 Vue3 + ECharts 开发交互式可视化大屏，直观呈现核心业务指标和分析结果。

| 图表类型 | 展示内容 |
|----------|----------|
| **数字卡片** | DAU、GMV、订单数、转化率等核心KPI |
| **折线图** | 用户活跃度趋势、日新增用户趋势 |
| **柱状图** | 商品热度排行、类目销售对比 |
| **漏斗图** | 浏览→收藏→加购→购买转化漏斗 |
| **饼图** | 行为类型分布、类目占比 |
| **热力图** | 用户活跃时段分布 |

## 数据集说明

**数据集名称：** UserBehavior（阿里天池公开数据集）

| 属性 | 说明 |
|------|------|
| **数据规模** | 100万+ 条行为记录 |
| **时间范围** | 2017年11月25日 - 2017年12月3日（30天） |
| **用户数** | 约 1 万独立用户 |
| **商品数** | 约 4 千个商品 |
| **类目数** | 约 4 千个商品类目 |
| **字段数** | 5 个字段 |

**字段结构：**

| 字段名 | 类型 | 说明 |
|--------|------|------|
| user_id | 整数 | 用户ID |
| item_id | 整数 | 商品ID |
| category_id | 整数 | 商品所属类目ID |
| behavior_type | 字符串 | 行为类型（pv/fav/cart/buy） |
| timestamp | 整数 | 行为发生时间戳（Unix时间戳） |

**行为类型分布：**

| 行为类型 | 占比 | 说明 |
|----------|------|------|
| pv（浏览） | ~90% | 商品详情页浏览 |
| cart（加购） | ~5% | 加入购物车 |
| fav（收藏） | ~3% | 收藏商品 |
| buy（购买） | ~2% | 提交订单购买 |

## 创新点与特色

1. **湖仓一体架构实践** — 基于 Apache Hudi 构建完整的湖仓一体数据平台，验证了开放表格式在电商用户行为分析场景下的技术可行性

2. **五层数仓规范落地** — 严格遵循 ODS→DIM→DWD→DWS→ADS 五层架构，结合 Kimball 维度建模理论，构建了规范的数据分层体系

3. **MOR/COW 混合表设计** — 针对不同层级的数据特性，灵活选用 MOR 或 COW 表类型，在写入性能与查询性能之间取得平衡

4. **会话划分算法** — 基于 Spark 窗口函数实现的 30 分钟超时会话切分，为用户行为路径分析提供基础

5. **全链路可视化** — 从原始数据到业务指标的端到端打通，配合 Vue3 + ECharts 实现交互式大屏展示
