五、创新实验

实验一 · 批流一体双链路入湖（Kafka + Structured Streaming）

目的验证湖仓对准实时增量数据的统一管理能力，构建"批量 + 流式"双写入链路。
方法kafka_producer.py 将 2017-12-03 当日清洗数据按 500 条/秒重放至 Kafka topic user_behavior_stream；streaming_to_hudi.py 以 Structured Streaming foreachBatch 微批 upsert 写入 Hudi MOR 表 ods_user_behavior_realtime（checkpoint 断点续传），主键/预合并键/分区与批量 ODS 表完全对齐。
验证实时表主键唯一性 / 分区分布校验通过；Hudi 增量查询：读取第 3 个 commit 之后的增量 = 微批 4 的 13,951 条，增量语义精确到 commit 级。
创新点同一湖仓内批量贴源与流式贴源双表口径对齐，为批流合一的实时数仓演进预留架构。

实验二 · MOR vs COW 表格式对照实验

目的为"湖仓表格式混选"提供实证依据，而非教条式单选。
方法同环境建对照表 test_hudi_mor / test_hudi_cow，执行相同写入与查询负载，对比两种格式的写入路径与读取代价。
结论验证"写多读少用 MOR（合并代价转移读侧）、读多写少用 COW（查询零合并）"的代价权衡，落地为 ODS=MOR、DWS/ADS=COW 的分层混选方案。
创新点按层读写特征混选表格式，并以对照实验 + 下游分区校验双重佐证选型正确性。

实验三 · 多口径数据质量校验体系（三角核对 + 21 项交叉校验）

目的让每个上屏指标都可回溯到明细、可证明可信。
方法DWS 层逐分区"三角核对"（明细 = Σ用户 = Σ商品 = Σ类目，四行为分别对账）；ADS 层 21 项多口径交叉校验（三层 DAU/GMV/漏斗一致、新老守恒、TopN 排序与并列、占比合计≈100%、热力图 Σ=明细数）。
结果六道质量闸门全 PASS；全链路重跑结果与基准逐位一致。
创新点把数据质量做成贯穿六阶段的工程闸门体系，而非事后人工抽检。

实验四 · 异常数据治理闭环 + 服务层弹性降级

目的治理真实数据中的脏数据；保证答辩/演示环境的鲁棒性。
方法异常分区 dt=2018-08-28（仅 16 条、游离主分析期 8 个月）：清洗层标记保留血缘 → ADS/CSV 导出双保险过滤 → 服务层 latestDt 口径恢复 2017-12-03；服务层读 ADS CSV 建内存索引实现零 Hadoop 集群依赖部署，缓存 Redis 不可用时自动降级 Caffeine 并在健康检查如实上报。
结果数据血缘与消费口径兼得；无大数据集群环境完成完整大屏演示。
创新点"分层治理、边界收敛"的数据质量闭环；演示架构与生产架构解耦的部署设计。
六道质量闸门：①清洗四项校验 ②入湖分区校验 ③分区级三角核对 ④21 项多口径交叉校验 ⑤接口冒烟 ⑥大屏验收 — 全 PASS
全链路脚本化，可一键重跑，重跑结果与基准逐位一致 ｜ 异常分区 dt=2018-08-28：清洗层保留血缘 → 服务边界口径收敛（质量闭环）
